# ipv6-classify

Expand, compress and classify IPv6 addresses — and find out when an address contains a
network card's MAC address.

One file, no dependencies, works in Node and the browser.

```js
const ip6 = require('ipv6-classify');

ip6.classify('2002:c000:204::');
// { type: '6to4 tunnel', note: 'tunnelled over IPv4, not native - usually slower than plain IPv4' }

ip6.classify('::ffff:1.2.3.4');
// { type: 'IPv4-mapped', note: 'an IPv4 address in IPv6 form, not native IPv6' }

ip6.compress('2001:0db8:0000:0000:0000:0000:0000:0001');  // '2001:db8::1'
ip6.expand('::1');                                        // ['0000', ..., '0001']
```

## The EUI-64 part

This is the reason the library exists.

An IPv6 interface identifier can be derived from the interface's MAC address. The transform
splits the six-byte MAC in half, inserts `ff:fe` in the middle and flips one bit. The MAC is
not hashed and not truncated — it is simply sitting there in the second half of the address,
and it follows the device between networks.

```js
ip6.isEui64('fe80::0202:b3ff:fe1e:8329');       // true
ip6.macFromEui64('fe80::0202:b3ff:fe1e:8329');  // '00:02:b3:1e:83:29'
```

Privacy extensions (RFC 4941) replaced this with rotating random identifiers, and modern
desktop operating systems use them by default. Plenty of embedded hardware, routers and older
kit still does not.

The check is positional, not a substring search: `ff:fe` has to straddle groups 6 and 7
specifically. An address that merely contains those bytes somewhere is not EUI-64.

## Types

| type | meaning |
|---|---|
| `global unicast` | A real, internet-routable address. |
| `6to4 tunnel` | Carried over IPv4, not native. Usually slower than plain IPv4. |
| `Teredo tunnel` | Also over IPv4, largely abandoned. |
| `link-local` | Never leaves your local network. |
| `unique local` | Private range, cannot reach the internet. |
| `IPv4-mapped` | An IPv4 address in IPv6 clothing — reported separately because it is not native IPv6 connectivity. |
| `documentation` | The `2001:db8::/32` example range. Not a real address. |
| `loopback` / `unspecified` | `::1` and `::`, kept distinct from each other. |
| `multicast` | |
| `other` | Valid, but unassigned or not otherwise interesting. |
| `unparseable` | Not a valid IPv6 address. |

`isGlobal(addr)` is shorthand for `classify(addr).type === 'global unicast'` — so tunnels,
mapped IPv4 and the documentation range all return `false`, which is usually what you want
when the real question is "does this host have working native IPv6?".

## API

| call | returns |
|---|---|
| `expand(addr)` | Eight four-digit lowercase groups, or `null`. Handles `::`, an embedded IPv4 tail and a `%zone` suffix. |
| `compress(addr)` | The canonical RFC 5952 form, or `null`. |
| `classify(addr)` | `{ type, note }`. |
| `isEui64(addr)` | Whether the interface identifier came from a MAC. |
| `macFromEui64(addr)` | The MAC it was built from, or `null`. |
| `isGlobal(addr)` | Routable global unicast only. |

## Tests

```
node tests/run.js                      # 116 checks
python tests/generate-vectors.py       # regenerate the reference vectors
```

`tests/vectors.json` is generated by **Python's `ipaddress` module**, which decides what each
address expands to and what its canonical compressed form is. This library has to agree.

CI regenerates the vectors with Python 3.10, 3.12 and 3.13 and runs the suite against each,
rather than byte-comparing the committed file. That is deliberate: comparing against a
committed file pins the repo to one patch release, and `ipaddress` changes. The committed
`vectors.json` is there so the suite runs without Python at all.

Compression is the part that is easy to get subtly wrong, and the vectors cover it: the
longest zero run wins, the leftmost wins a tie, and a single zero group is never compressed.

Two things worth knowing if you extend the tests.

**`ipaddress.is_global` is registry-based.** It means "not in a special-purpose registry", so
it is `True` for multicast `ff02::1` and for unassigned space like `1:0:0:2::3`. It is not a
synonym for global unicast, and treating it as one produces confident nonsense.

**`ipaddress` is not a fixed reference.** Two things changed *within* the 3.12 series:
`is_private` / `is_global` in the CVE-2024-4032 fix, and the rendering of IPv4-mapped
addresses, which went from `::ffff:c0a8:1` to `::ffff:192.168.0.1`. Both broke CI on vectors
that were correct when they were generated.

So the vectors record only `exploded` and `compressed` for addresses where Python is stable.
Address categories are asserted by hand, and IPv4-mapped rendering is asserted against
**RFC 5952 section 5**, which is what settled the question — a reference that disagrees with
itself across patch releases cannot arbitrate.
